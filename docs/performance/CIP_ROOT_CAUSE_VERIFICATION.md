## Corrections to earlier narratives

- The database account's 11.8178 cumulative hours are not all CIP; the account also ran explicitly unrelated product SQL. Query-by-query attribution is required.
- CIP-account activity during the October 21 ChainXY lock interval does not prove CIP held or caused the metadata lock.
- `(survey_id,qcode)` is already a left prefix of `srv_answer`'s primary key. No redundant index is proposed.
- `using_temporary_table=true` proves an internal temporary grouping operation, not a physical disk spill. `Created_tmp_disk_tables` or equivalent isolated instrumentation is required.
- Publisher reads use the `app` engine. The repository's 512 MiB `ETL_SESSION` settings apply only to non-app/writer engines; they are not publisher session settings.
- `jobs=4` is the current default and weekly caller does not override it, but that does not prove four simultaneous historical queries.
- Cumulative SQL elapsed time is not outage duration, CPU time, or IOPS share. Query-family groups may overlap and must not be summed blindly.

## Current publish invalidation behavior

Incremental publish and hard-link reuse were already present in source committed on 21–22 October. A wave is rebuilt when `srv_wave.built_at` changes, required audience files are absent, rules change, or the prior live build cannot be reused. This reduces current repetition, but it does not explain why 681 historic group statements ran: deployed revision, initial/rules-driven rebuilds, retries, and run IDs are missing.
