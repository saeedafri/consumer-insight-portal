# Consumer Intelligence Platform | Engineering and Ask CIP review

**20 November 2026 · Decision for Product, Research, Engineering and IT**

Keep the current precomputed serving architecture. Hold external expansion until credential incident closure, tenant-aware result assembly and atomic publication are verified. CIP can already serve common views quickly. The biggest customer risks are a plausible answer with the wrong evidence, disclosure across access scopes, and a green deployment that serves stale or incomplete data.

The first Ask changes in this workspace address evidence and interaction. Each displayed percentage can carry its own sample size. Choosing a suggested question preserves its identity. Clearing or replacing an in-flight question removes its right to update the page. A successful optional check can correct the period or cut. The new training workflow belongs in a measured experiment on top of those contracts.

### How to improve each layer

1. **ETL speed and correctness.** Build a stage profile from fixed inputs before changing the engine. Measure source wait and retries, rows streamed, per-wave bytes, SQL plans and query time, changed-family work, hard-link operations, gzip time, and warmup. Rebuild only affected stable question families. A publication currently schedules up to 1,230 sequential crosstab warm requests for one 41-question tracker wave. Move warmup outside the writer lock and warm the top routes from real usage. Keep checksums and content validation. [Publication and warmup](../../etl/publish.py#L388)
2. **Resource isolation.** Start with one web worker sized by mixed evidence. Isolate ETL and heavy export capacity, restrict ONNX thread count, and expose queue depth, cancellations, CPU throttling and memory high-water marks. Require a reproducible peak memory margin during model load, generation swap, and export concurrency. Two workers multiply indexes, pools, caches and in-process model assets. Scale after state and authorization are shared safely.
3. **Cache order and fallbacks.** Static browser/CDN cache only for public and immutable assets. Nginx versioned files for shared accessible results. Application cache for scoped dynamic queries. Use generation, permission context, semantic query and format as identity. Serve last verified data with age and explicit status when a fresh generation fails. Keep expensive live fallback bounded and opt-in by route. Use a typed busy/error response and jittered retry rather than a synchronized retry storm. [Nginx](../../deploy/cip_locations.conf#L41) · [Application](../../api/main.py#L384) · [Browser](../../frontend/src/api.ts#L68)
4. **Build time and disk.** Time npm install, Python/native deps, model downloads, type-check, static export, gzip, layer upload, boot and ready. Pin build inputs and external artifact checksums, reuse dependency layers keyed by lockfile, publish by immutable digest, and prebuild approved model artifacts. Put alerts on free bytes and inodes, cache and layer growth, tar/temporary peaks and archive retention. Rehearse a full restore from independently retained artifacts. [Docker](../../deploy/Dockerfile#L6) · [Backup](../../scripts/backup_db.py#L102)
5. **Operational visibility.** Capture a per-journey trace from browser to Nginx, API, SQL, export or model. Tag every segment with release and data generation. Track the age of last successful publication, public readiness and authenticated smoke results separately. Log alert delivery outcomes durably. ## 4. What analysts need from surveys

**Demand evidence.** Coresight’s public US survey index shows weekly shopping behavior and spending, monthly outlooks, retailer comparisons, income cuts and trends. Its 11 November holiday report compares equivalent weeks and separates shopping progress, recent purchase behavior, retailers and categories. The checked-in training history records 65,688 historical Ask audit events, dominated by scripted traffic. The researchers identified four real accounts and 55 distinct questions outside the golden set. Fifty were adjudicated for the regression suite, then used to improve the application. This is direct evidence of real phrasing and a small sample for prioritization. It supplies neither market-wide question frequencies nor a fresh holdout. ### Answer design

Start with **one sentence that resolves the question**. For example, using fictional data: “40.0% bought groceries online in the 9 November wave, 5.0 percentage points above the prior comparable wave.” Under that, display **120 of 300 eligible respondents · United States · unweighted** and a direct source link. Give the reader one relevant chart or comparison, an expandable evidence table, a short interpretation grounded in those figures, and useful next actions such as Compare or Download.

For an ambiguous question, replace the headline with a two- or three-option choice stated in plain language. For missing or unsupported evidence, state the specific limitation first. Use status language with clear consequences: “Best match,” “Choose a survey question,” “No comparable wave,” and “Available through Cross-tabs.” Keep accessibility status brief and offer two routes to chart data, a visible table and a data export. Saved links and exports should preserve filters, weighting, question and source generation.

## 5. Ask CIP architecture, low-cost training and new data

### Serving design

1. Parse the request into a typed intent: measure, question/item/answer, operation, geography, dates and completeness, population, filters, weighting, comparison type and desired output. Keep selection, answerability and ability to execute as separate decisions.
2. Scope the catalogue **before** candidate generation. Return exact approved question identity for an explicit selection. For free text, combine existing aliases, lexical search and embeddings, then use a small local reranker only when the cheap evidence is insufficient.
3. Check each requested operation, cohort, date and source. Never replace an unavailable subgroup with Total or a later period with the latest available. Use reviewed semantic IDs and reject non-comparable waves. Multi-step joins only through approved operations using matched populations and denominators.
4. Produce one deterministic evidence result with each cell’s count, denominator, share, disclosure state and source wave IDs. Build the headline, chart, table, follow-up and exports from it. Keep model-generated language optional and grounded in that result. Paid verification must not receive raw respondent data or be required for standard results.
5. On publish, validate and build the new catalogue, alias map and changed embeddings before making it active. Track the generation and data-through date in responses. Scope every answer cache by generation, entitlement, query and effective model. Use a previous complete generation if a fresh one fails. Evaluate the same semantic intent after a new wave, a renamed code, a removed answer, a changed denominator and a revocation.

This design keeps frequently asked questions and exact selections on the inexpensive path. A new wave updates the catalogue and figures without retraining. Recalibration or retraining is triggered by measured retrieval, intent or abstention drift. Keep the active checkpoint pinned and switch candidates by version after shadow evaluation.

### What to train first

The recorded v8 experiments improved retrieval rank on some sets and still **lost two golden cases** after integration. Large readers took around **1.1 s** on the Mac and did not improve the golden score. Start with a single compact reader candidate and fix intent and ground truth first. Test retrieval recall at K before reranking. A reader cannot recover an answer excluded from its candidate list. Measure confidence thresholds from untouched validation cases and combine them with hard execution checks. [CIP v8 report](ask-cip-model-training.md#L1225) · [Cross-encoder training](https://www.sbert.net/docs/cross_encoder/training_overview.html) · [Selective classification](https://proceedings.mlr.press/v97/geifman19a.html)

Use a six-stage corpus:

1. **Acquire real demand with permission.** Collect approved analyst questions and intended outcomes. Strip raw logs, identifiers, respondent data, secret files and tenant metadata. Record the exact wording only under the applicable data-use policy. Keep test cases with no data and disabled access.
2. **Adjudicate 500–1,000 pilot cases.** Cover easy lookups, filters, wording variants, overlap nets, longitudinal changes, missing periods, China/US, weighting, ambiguity, chained follow-ups and hard near misses. Two reviewers for high-risk stats, comparability and eligibility. Record the authorized visible wave set, exact evidence cells and a reason for abstention.
3. **Generate practice at scale.** After a small pilot improves the held-out result, generate 100,000–300,000 candidate pairs with dates, aliases, population and operator perturbations. Generated pairs are weak training data. Same question variants and recodes can be multiple valid labels. Review close negatives and deduplicate by normalized question, concept and time. Use independently produced sets for scoring. [Hard-negative research](https://aclanthology.org/2025.findings-emnlp.481/)
4. **Partition before training.** Hold out whole concept families and their aliases, recent waves strictly after the training cutoff, private/enforcement fixtures, locale slices and new-question tests. Use a separate development partition for thresholds. Freeze the release set before training. Scores on synthetic, matched expert, fresh human and future-wave slices remain separate.
5. **Evaluate paired runs.** Run candidate and shipped checkpoint on identical inputs. Record Recall@K, selection exactness, supported-intent coverage, wrong confident answers, false abstentions, exact cell/base/source matches, permission correctness, p95 and p99 latency, memory, CPU and per-answer costs. Score chart values, ranks, labels, citation provenance and export contents through actual product entry points.
6. **Promote only with evidence.** Require zero wrong-source permissions and zero materially incorrect figures on approved exact fixtures, then show better wrong-answer and coverage tradeoff on held-out expert and future cases without a compute-budget regression. Review slice sample sizes and uncertainty. Roll back by checkpoint and generation if observed quality falls.

Spider 2.0 and BIRD inform multi-step and dirty-data cases. TAT-QA and FeTaQA illustrate evidence-cell grounding and arithmetic. Use their methods for evaluation design and define CIP's truth from licensed surveys. [Spider 2.0](https://arxiv.org/abs/2411.07763) · [BIRD](https://arxiv.org/abs/2305.03111) · [TAT-QA](https://aclanthology.org/2021.acl-long.254/) · [FeTaQA](https://aclanthology.org/2022.tacl-1.3/)

### Answer contract

- **First line.** Answer the user's question in one plain sentence. Include the measure and direction. Use “percentage points” for subtraction of shares. When the user asks about one subgroup, name it in the sentence.
- **Evidence line.** Show actual dates, country, number of contributing waves, weighting status and a source link. Expose exact answer and sample sizes by cell. Let a reader check survey wording behind the chart and export.
- **Complex requests.** Match each supported subquestion to a typed operation and a source. One subquestion may be answerable while another lacks a measure or comparative base. Put any caveat next to its finding. For example, answer the January–February overall comparison, mark rural change unavailable, and explain which evidence would be needed for causality. General execution of multiple operations in one reply remains a planned enhancement.
- **Use computation once.** Derive shares from counts and valid denominators, changes from the same displayed shares, ranks from the same series, and rounding only at the display boundary where applicable. The wording, table, chart and downloads consume that result. If wording is ever model-assisted, give it references to already computed values. Keep a deterministic fallback, and test that every claim reconciles to the table.
- **Guide ambiguous input.** Offer a few precise choices such as buying from Amazon, Prime membership, or a specific sale event. Preserve the dates and selected question. One focused follow-up should advance the analysis.

**Implemented here:** Ask leads with the finding and links the actual data scope immediately below it. It uses full unit labels, keeps detailed KPI tiles in Analyst view, and opens the same per-cell evidence from either view. Source history uses the caller's visible wave list. The citation uses the actual question code and wording from the contributing wave, including when that question was renumbered. A synthetic two-wave fixture previously linked the old figure to the new code, which could silently open an unrelated question. Tested causal wording now yields a plain explanation instead of a nearby share. The next products to build are explicit measure disambiguation, a complete typed multi-part result, and consistent citation for every executed part.

### Store evidence and hot results

Store canonical survey question IDs, answer options, permitted cross-wave versions, compact result arrays, approved aliases, and model weights. Maintain small rolling result caches tied to generation and entitlement. Compute supported requests from these facts at runtime. Generated variants belong in offline evaluation and training bundles. They never belong in the serving catalogue.

A complex survey engine can combine a few checked operations on published aggregates or approved respondent indexes. Use explicit support and cost limits. The hot path can reach microseconds inside one process for an in-memory hit. A cache miss still does useful work, and the browser still pays transport and rendering time. The release target is exact evidence for every reported figure, explicit refusal for missing evidence, and separate latency budgets for each class of request. Unrestricted accuracy and microsecond end-to-end completion are not valid targets for arbitrary questions.
